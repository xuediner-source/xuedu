# Backend deployment notes

Run the backend behind the TLS Nginx virtual host. Keep `BIND_HOST=127.0.0.1` so the service is reachable only through the local reverse proxy, and give it a private `DATA_DIR` owned by the service account.

CAS and the academic system use HTTPS by default. `CAS_BASE_URL` and `EDU_BASE_URL` can point to approved HTTPS endpoints; startup rejects HTTP URLs, and redirected requests are also restricted to HTTPS. The public school identity portal at [ids.cqjtu.edu.cn/authserver/login](https://ids.cqjtu.edu.cn/authserver/login) was checked over HTTPS without submitting any credentials.

Real session cookie jars are encrypted with AES-256-GCM and written atomically with mode `0600` inside a mode `0700` data directory. To enable persistence, set `SESSION_ENCRYPTION_KEY` to a random 32-byte key encoded as 64 hex characters or base64. Keep that key in the service secret store and back it up with the service configuration. If it is absent, live sessions stay in memory only; the login response tells the client that a server restart requires signing in again. Gray demo sessions never persist and work without this key.

Legacy `sessions.json` files from earlier versions contain unencrypted cookies. When the new key is configured, the backend reads valid legacy sessions once and rewrites them in the encrypted format. If no key is configured, it discards that legacy session file and requires a new login. An encrypted session file that cannot be authenticated is left untouched and sessions are not restored; check that the original key is configured. Changing the key invalidates existing persisted sessions, so users must sign in again.

Set `SESSION_TTL_SECONDS` to an integer from 60 seconds to 90 days; the default is 14 days. `UPSTREAM_TIMEOUT_MS` accepts 1,000–120,000 milliseconds; the default is 15 seconds. Login attempts are limited to eight per client IP in each 15-minute window.

The fictional demo feature is off unless `DEMO_ENABLED=1` is explicitly set. `GRAY_ENABLED` remains a compatibility alias when `DEMO_ENABLED` is absent. This is a demo switch and does not select or gate an APK release. For a local demo, use a temporary data directory and set that variable to `1`; the sample fictional account is `xuedu_demo` / `xuedu2026`. These are demo credentials and do not grant management access. The legacy `/api/gray/control` endpoint is unavailable until both `GRAY_ADMIN_TOKEN` and a comma-separated exact-IP `GRAY_ADMIN_IPS` allowlist are configured. The Nginx exact-location rule below also defaults to denying remote access; add each authorized source IP there and in `GRAY_ADMIN_IPS` to enable management. Runtime control can turn the switch off; turning it on still requires `DEMO_ENABLED=1` and a service restart after changing environment configuration.

Android test release metadata lives in [app-release.json](../backend/app-release.json). The initial `0.0.1` / code `250` release is marked `published: false` until the GitHub release asset is uploaded and verified. Set `published` to `true` only after confirming the asset URL is reachable; the backend accepts only HTTPS GitHub release APK URLs. `/download/app-test.apk` is the sole canonical redirect, and the former `app-gray.apk` and `app-latest.apk` paths redirect there. The update API compares a supplied positive `versionCode` first so `0.0.1` can follow a prior `2.2.x` build; it falls back to semantic version comparison when no code is supplied. An unpublished or invalid release returns `updateAvailable: false` and no download URL.

The course-start date table is [semester-dates.json](../backend/semester-dates.json). It carries the existing project configuration for `2026-2027-1`, `2026-09-07`; this change did not re-verify that date against the school calendar. Check the current school calendar before deployment. Add another semester only after its actual first teaching date is confirmed. Until then, the API returns an empty `semesterStart`, `semesterStartKnown: false`, and `currentWeek: null` for that term. `semesterStartKnown` means that the API has a valid configured date; it does not claim this run independently verified the source.

Install and verify from `backend/` with `npm ci` and `npm test`. Local tests use temporary directories and fictional demo data; they do not access real student accounts or deploy anything. The mini program defaults to the HTTPS backend URL; set `USE_LOCAL_BACKEND=true` in `miniprogram/config.js` only while using WeChat developer tools with a local backend.
